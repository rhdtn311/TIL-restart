### 1. 트랜잭션의 ACID 속성

트랜잭션(Transaction)이 안전하게 수행됨을 보장하기 위해 데이터베이스 관리 시스템(DBMS)이 지켜야 하는 4가지 핵심 속성은 다음과 같다.

* **원자성(Atomicity):** "All or Nothing" 원칙에 따라 트랜잭션 내의 모든 작업은 하나의 단위로 취급된다. 작업이 모두 성공하여 반영되거나, 하나라도 실패할 경우 전체가 취소되어야 한다.
* **일관성(Consistency):** 트랜잭션 완료 후 데이터베이스는 비즈니스 로직에서 정의한 모든 제약 조건과 규칙을 만족하는 상태를 유지해야 한다.
* **격리성(Isolation):** 동시에 실행되는 여러 트랜잭션은 서로의 중간 상태에 간섭하지 않고 독립적으로 수행되어야 한다. 이는 **격리 수준(Isolation Level)** 설정과 직결된다.
* **지속성(Durability):** 성공적으로 완료(Commit)된 트랜잭션의 결과는 시스템 장애가 발생하더라도 데이터베이스에 영구적으로 기록되어 보존되어야 한다.

---

### 2. 격리성과 트랜잭션 격리 수준의 관계

격리성을 완벽히 보장하기 위해 모든 트랜잭션을 순차적으로 처리하면 데이터 정합성은 완벽해지나, 시스템의 동시 처리 성능(Throughput)이 급격히 저하된다. 반대로 격리를 느슨하게 하면 성능은 향상되지만 데이터 부정합 문제가 발생할 가능성이 커진다.

**트랜잭션 격리 수준**은 이러한 **성능(Concurrency)과 데이터 정합성(Consistency) 사이의 트레이드오프(Trade-off)**를 조절하는 설정이다. 격리 수준이 높을수록 데이터는 안전하지만 처리가 느리고, 낮을수록 속도는 빠르지만 데이터 오류 위험이 증가한다.

### 3. 동시성 제어 시 발생하는 주요 문제

여러 트랜잭션이 동일한 데이터에 동시에 접근할 때 발생하는 대표적인 부작용은 다음과 같다.

#### 3.1. Dirty Read

트랜잭션 A가 수정한 데이터를 **커밋하기 전에** 트랜잭션 B가 읽는 현상이다. 만약 트랜잭션 A가 롤백(Rollback)된다면, 트랜잭션 B는 존재하지 않는 데이터를 바탕으로 로직을 수행하게 된다.

```sql
시간순서    트랜잭션 A                        트랜잭션 B
────────────────────────────────────────────────────
t1        UPDATE Applicants
          SET status = 'REJECT'
          WHERE user = '태현';
          ('SUBMIT' -> 'REJECT')
t2                                        SELECT status
                                          FROM Applicants
                                          WHERE user = '태현';
                                          → 결과: 'REJECT' (Dirty Read 발생)

t3        ROLLBACK;
          (다시 평가단계(SUBMIT)으로 복구)

```

#### 3.2. Non-Repeatable Read

한 트랜잭션 내에서 **같은 데이터를 두 번 조회했을 때 그 값이 서로 다른** 현상이다. 첫 번째 조회와 두 번째 조회 사이에 다른 트랜잭션이 해당 데이터를 수정하고 커밋했기 때문에 발생한다.

```sql
시간순서    트랜잭션 A                        트랜잭션 B
────────────────────────────────────────────────────
t1        SELECT totalScore
          FROM Applicants
          WHERE user = '태현';
          → 결과: 100점

t2                                        UPDATE Applicants
                                          SET totalScore = 50
                                          WHERE user = '태현';
                                          COMMIT;

t3        SELECT totalScore
          FROM Applicants
          WHERE user = '태현';
          → 결과: 50점 (값이 변함, Non-Repeatable Read 발생)

```

#### 3.3. Phantom Read

한 트랜잭션 내에서 동일한 조건으로 범위를 조회했을 때, **처음에는 없던 레코드가 다시 나타나는** 현상이다. 다른 트랜잭션이 조건에 부합하는 새로운 데이터를 삽입(Insert)하고 커밋했을 때 발생한다.

```sql
시간순서    트랜잭션 A (집계)                   트랜잭션 B (신규 지원)
──────────────────────────────────────────────────────────────────
t1        SELECT COUNT(*) FROM application
          WHERE position = 'BACKEND_ENGINEER'
          AND status = 'SUBMIT';
          → 결과: 10건

t2                                          INSERT INTO application
                                            (position, status)
                                            VALUES ('BACKEND_ENGINEER', 'SUBMIT');
                                            COMMIT;

t3        SELECT COUNT(*) FROM application
          WHERE position = 'BACKEND_ENGINEER'
          AND status = 'SUBMIT';
          → 결과: 11건 (새로운 레코드 출현, Phantom Read 발생)

```

### 4. 트랜잭션 격리 수준(Isolation Level)의 종류

#### 4.1. READ UNCOMMITTED (Level 0)

가장 낮은 격리 수준으로, 커밋되지 않은 데이터에 대한 접근을 허용한다. Dirty Read를 포함한 모든 동시성 문제가 발생할 수 있어 실무에서는 거의 사용되지 않는다.

#### 4.2. READ COMMITTED (Level 1)

커밋이 완료된 데이터만 읽을 수 있도록 보장한다. Dirty Read는 방지되나, Non-Repeatable Read와 Phantom Read는 발생할 수 있다. **Oracle, PostgreSQL** 등 대다수 RDBMS의 기본 격리 수준이다.

#### 4.3. REPEATABLE READ (Level 2)

자신의 트랜잭션이 시작되기 전에 커밋된 내용만 조회하며, 동일 트랜잭션 내에서는 일관된 읽기를 보장한다. Dirty Read와 Non-Repeatable Read를 방지한다.

> **참고:** MySQL(InnoDB)은 MVCC와 Gap Lock을 활용하여 이 수준에서도 Phantom Read를 효과적으로 방지한다.

#### 4.4. SERIALIZABLE (Level 3)

가장 높은 격리 수준으로, 트랜잭션을 순차적으로 실행하는 것과 동일한 결과를 보장한다. 모든 SELECT 문에 공유 잠금(Shared Lock)을 설정하여 데이터 정합성을 완벽히 보호하지만, 동시 처리 성능이 가장 낮다.

### 요약

트랜잭션의 안전성을 보장하는 **ACID 속성** 중 격리성은 시스템 성능과 데이터 정합성 사이의 균형을 맞추는 핵심 요소다. 개발자는 비즈니스 요구사항에 맞춰 **4가지 격리 수준** 중 적절한 단계를 선택하여 Dirty Read, Phantom Read 등 동시성 문제를 제어해야 한다. 특히 사용 중인 DBMS의 기본 격리 수준과 특성을 파악하여 예상치 못한 데이터 부정합을 방지하는 것이 중요하다.
